# Contracts — публичные границы завершения M1

Точные DTO и ошибки принадлежат публичным `@warwrit/protocol` и серверным
адаптерам. Ниже зафиксированы текущие входы и целевые гарантии.

## Текущие входы

| Вход                                    | Идентичность и формат                                                              | Наблюдаемый контракт                                                                |
| --------------------------------------- | ---------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| POST /contracts/ordinary/commands       | warwrit_session, OrdinaryContractCommandDto в `packages/protocol/src/contracts.ts` | Аутентификация → владение компанией и блокировки → квитанция → допустимый результат |
| POST /contracts/commands                | Та же сессия, действующий контрактный DTO                                          | FIRST HUNT, участие, допуск, доказательство и собственная политика трофея           |
| GET /dev/combat-lab/catalog             | Существующий локальный dev-вход                                                    | Каталог доступных профилей и карт                                                   |
| POST /dev/combat-lab                    | Текущий create/config DTO                                                          | Создание временной сессии, capability в x-combat-lab-capability                     |
| GET /dev/combat-lab/:sessionId          | Тот же capability header                                                           | Разрешённая проекция, предпросмотр включён в ответ                                  |
| POST /dev/combat-lab/:sessionId/actions | Тот же capability header, действующий action DTO                                   | Проверенный actor, revision и действие, согласованный результат повтора             |
| GET /dev/combat-lab/:sessionId/replay   | Тот же capability header                                                           | Реплей своей доступной сессии                                                       |
| DELETE /dev/combat-lab/:sessionId       | Тот же capability header                                                           | Завершение принадлежащей вызывающему временной сессии                               |

В browser-клиенте действует существующий dev proxy /api. Точные mount paths
и DTO проверяются в выбранной базе перед изменением адаптера.
Session capability хранится клиентом вместе с ID в sessionStorage.
Она передаётся заголовком и исключается из экспортируемого конфига и публичных логов.

## Новый многосоставный формат

Целевая редакция — setup/replay schema 3 и lab config/protocol 2.
Создание сессии выбирает codec по явной версии входного формата.
Ответ и дальнейшие чтения сохраняют выбранную версию сессии.
Readers старых config 1 и setup/replay 1/2 маршрутизируются к своим правилам.
Клиентский controller декодирует поддержанные версии до использования данных.

Новая конфигурация передаёт все side IDs, группы, unit IDs, стороны участников,
зоны отхода и полный состав. Допуск валидирует 2–3 стороны, до 12 на сторону,
до 36 всего, уникальность, свободные законные позиции и членство.
В кампании до 6 бойцов допускается от одного отряда игрока.

Сервер вычисляет доступные вызывающему unit IDs по своему контексту владения.
Состав союза и право командовать бойцом проверяются отдельно.
Проекция, очередь, выбор цели, предпросмотр и итог сохраняют все стороны.
Клиентские actor/party/side strings служат ссылками на проверяемые сущности.

Текущий battle config экспортирует version/name/seed/map/units, карта —
version/name/tiles, replay — schemaVersion/setup/commands.
Новая версия расширяет контракт состава согласно [модели](../data-model.md).
Round trip проверяет идентичность, позиции, зоны отхода и управление.

## Сохранённая команда и выплата

Обычный путь — `apps/server/src/contracts/ordinary.ts` через
executeCommandTransaction и executeOrdinaryCommand.
Сессия подтверждается до исполнения. Внутри проверяется владелец компании,
блокируются контракт и компания, затем читается private receipt.
Ключ world/company/command ID связывается с canonical request key полного запроса.

- Точный повтор возвращает сохранённый ответ, включая повтор после более поздних изменений.
- Тот же ID с изменённым телом возвращает действующий отказ INVALID_COMMAND.
- Недопустимый актор получает отказ по полномочиям, сведения чужой квитанции сохраняют приватность.
- persistContractRewardPayment, контракт, кошелёк заказчика, снимок компании,
  контрактная квитанция, company_receipts и аудит фиксируются в одной транзакции выплаты.

Кампания использует свою границу терминального исхода и последующее применение
pending effects из `apps/server/src/encounters/effects.ts`.
Терминальный маркер и атомарный commit последствий проверяются раздельно
по N11/R2. Сбой между ними оставляет сохранённый исход с ожидающими обработки
последствиями. После перезапуска используется существующий допустимый переход,
включая предусмотренное ожидание выбора лидерства. Освобождение компаний
фиксируется вместе с применёнными последствиями по правилам исхода.

## Остальные публичные границы

| Путь игрока                               | Владелец формата                                                 | Гарантия                                                                              |
| ----------------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| Компания, услуги, курс, прозвище, продажа | `packages/protocol/src/company.ts`, server company и N03/N04/N06 | Поставщик, средства, состояние и полномочия проверены, обязательные эффекты сохранены |
| Маршрут, остановка, атлас, место          | `packages/protocol/src/world.ts`, server world и N07             | Версия пути и время сохранены, сведения соответствуют наблюдателю                     |
| Сюжет, четыре моральные развилки, отчёт   | Владельцы B4, M1-QUESTS и M1-OFFLINE-REPORT                      | Личные сведения, один общий исход и действительный потребитель последствия            |
| Готовность и восстановление               | N11/N12 и существующий серверный health                          | Готовность отражает обязательные зависимости, сохранения возвращают обычный путь      |

## Матрица проверки границы

MULTI-1–MULTI-8 проверяют новый состав, версии, права и вид.
N11/R1–R4 проверяют сбои допуска, терминального применения и выплаты,
конкуренцию, exact retry и private readback. R5 подтверждает восстановление
на отдельном ресурсе через вход и продолжение компании.
[Quickstart](../quickstart.md) связывает эти проверки с командами и владельцами.
