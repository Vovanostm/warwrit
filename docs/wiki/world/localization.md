# Переводы

## Сейчас

Игровые строки на русском лежат прямо в компонентах: `CONTRACT_TEXT`,
`STEP_TEXT`, `FINDINGS` в `apps/web/src/game/ContractBoard.tsx`,
названия мест там же и в `place-buildings.ts`, подписи создания компании
в `apps/server/src/company/opening.ts`. Падежи мест («в Тихой Гати»)
захардкожены отдельной таблицей. Системы локализации нет.

## Предлагаемое устройство

1. **Один ключ — одна строка.** Ключ строится из устойчивых ID игры:
   `contract.ci.m1.road-tracks.01.brief`, `contract.ci.m1.road-tracks.01.step.inspect-bank`,
   `place.kamenny-brod.name`. Текст не используется как ключ.
2. **Файлы:** `apps/web/src/locales/ru/*.json` — исходник, `en/*.json` — перевод;
   по файлу на область: `contracts`, `places`, `people`, `ui`, `errors`.
   Сервер отдаёт ID, клиент показывает текст. Канонические факты в текст не попадают.
3. **Формат ICU MessageFormat.** Он покрывает русские падежи, род и числа:
   - род героя и спутников: `{gender, select, male {задержался} female {задержалась} other {задержались}}`;
   - числа: `{n, plural, one {# крона} few {# кроны} many {# крон} other {# кроны}}`;
   - падеж места — отдельный ключ (`place.tikhaya-gat.in` = «в Тихой Гати»),
     потому что в других языках предлог и падеж устроены иначе.
4. **Без склейки строк.** Никаких `'нужно быть в ' + place`: только целая фраза
   с параметром. Иначе перевод ломается на порядке слов.
5. **Комментарий для переводчика** рядом с каждой строкой сюжета:
   кто говорит, кому, о чём молчит, длина. Для этого рядом с JSON лежит
   `*.notes.json` с теми же ключами.
6. **Глоссарий** — [glossary.csv](../../content/world/glossary.csv). Имена людей
   и мест транслитерируются (Kamenny Brod, Agafya), должности и общие слова
   переводятся (steward, toll clerk). Значимые прозвища переводятся,
   если смысл важен для сцены. Решение по каждому слову в колонке `rule`.
7. **Пол героя.** Имя задаёт игрок; при создании нужен выбор формы обращения
   (он/она), иначе русский текст о герое невозможно согласовать.
8. **Проверка.** Скрипт сверяет, что у каждого ключа `ru` есть все языки
   (или помечен как непереведённый), и что параметры ICU совпадают.

## Сделано — 2026-10-07

- Модуль [apps/web/src/i18n](../../../apps/web/src/i18n/index.ts): `ru.ts` —
  исходные строки, `en.ts` — перевод. Вместо JSON — объекты TypeScript:
  тип `Record<MessageKey, string>` не даёт собрать игру, если в переводе
  нет хотя бы одного ключа. Комментарии для переводчиков пока не заведены.
- Каталог разбит по областям: `<область>.ru.ts` и `<область>.en.ts`
  (сейчас `contracts`), `ru.ts`/`en.ts` их собирают. Каждая новая задача
  заводит свою пару файлов, чтобы агенты не правили один файл.
- Язык: `?lang=en` в адресе (запоминается), иначе сохранённый выбор, иначе русский.
- Переведены тексты восьми контрактов, названия мест и районов, заказчики охот,
  имена спасённых. Кнопки, ошибки и остальной интерфейс пока русские и
  в компонентах.
- Новых зависимостей нет. ICU (род, числа) понадобится, когда в строки
  попадут имя героя и суммы; тогда выбрать библиотеку.

## Порядок внедрения

Первый шаг — вынести строки восьми контрактов и мест в `ru`-файлы
вместе с переписанными текстами [Поречья](porechye.md) и добавить `en`.
Остальной интерфейс переносить по мере правки экранов.
Выбор библиотеки (например, `@formatjs/intl` или `i18next` с ICU)
требует проверки зависимостей и решения при реализации.
