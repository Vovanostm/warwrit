These sources favor a bounded, fully observable slice and explicit coordination,
then a matched repeat to measure local results. They do not establish that twelve
agents are optimal. With strongly sequential work, more workers can add handoff
cost, inconsistent assumptions, and review load. Configuration capacity is not
the same as parallelizable work.

## Capacity preparation and activation

The reviewed configuration was applied to the primary project using legacy
`agents.max_threads = 12` for installed CLI 0.144.5. A sanitized `config/read`
through that CLI returned the project limit and four role registration paths. The
implementer, reviewer and orchestrator TOMLs pin Luna/Sol/Astra at high reasoning;
`tomllib` confirmed those values, while `config/read` exposes paths, not per-role
model settings. This CLI rejects `max_concurrent_threads_per_session` and
`default_subagent_*` as role entries, so pin Luna for explorer dispatch. c06's CLI
0.146.0 accepts the newer keys.

This is configuration and loader readback, not proof that twelve spawned threads
can run. The last observed live runtime remains parent plus two child slots; no
fresh-session, role-launch or twelve-agent capacity test was run. Keep concurrency
at parent plus two until a fresh-session readback establishes actual capacity. No
role grants permission to merge, deploy, or change shared resources.

## Measurement record for each finished packet

Record these fields in the packet handoff, with evidence links:

- `start_utc` and `end_utc`;
- `revision` plus the exact dirty-tree identity when uncommitted;
- `accepted_playable_result`: yes/no, the parent decision, and the observed path/artifact;
- `blocked_time`: minutes only when start/end of the blocking interval were observed;
- `evidence`: commands, routes, database/browser artifacts and actual outcomes;
- `review_returns`: count and outcome of independent review cycles, with reviewed revision.

Missing historical fields stay `NOT_MEASURED`. Compare only materially equivalent
outputs with the same acceptance threshold, account for review/correction and
blocked time, and include verification cost. Report results as observations, not
claims of optimality or a general Luna productivity estimate.
