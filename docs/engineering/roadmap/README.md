# Roadmap navigation and maintenance

Owner decision — 2026-11-08. [ROADMAP](../ROADMAP.md) is the sole project-state
entry point. It contains only checkbox links; read only the document for the
requested task, not every linked page.

- `[x]` means the linked task's stated done criterion was demonstrated.
- `[ ]` includes planned, active, partially delivered, blocked or unverified work.
  The linked document explains which applies; a prepared contract or merged
  helper alone does not complete a player journey.
- Keep the index at milestone/feature granularity, normally within 50 lines.
  Move subtasks, dependencies, rules, instructions and evidence into owning files.
- Reuse work packages and wiki pages. Create a detail file here only when no
  suitable owner exists. Avoid competing status lists and duplicate specifications.
- In a task document keep one current status section: date, outcome/scope, next
  action, blockers, checks/limits and delivery state (local/published/merged).
  Add ownership, branch and explicit permission pointers only where relevant.
- Replace stale operational summaries instead of appending a session diary.
  Preserve decisions and detailed evidence at their original owner; link them.
- Update the task document first, then the roadmap checkbox when its criterion
  changes. Git/GitHub prove live revision/PR state; a checkbox is no merge permission.
- Use [warwrit-changelog](../../../.agents/skills/warwrit-changelog/SKILL.md)
  for a short change entry and bounded reading/search.
