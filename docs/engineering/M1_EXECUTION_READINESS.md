## Evidence and decision

The live M1 supporting index, refreshed September 29, defines `I02 <- I01 + F01 +
D02`, `W04 <- W03 + I02`, and `CT02 <- CT01 + I02 + ID03 + W06`.
F01 requires an authentic significant deed, cultural text, consent and history.
If its first real producer is a contract rescue, the producer chain is
`F01 <- CT04 <- CT02 <- I02 <- F01`. The static dependency table omits that
producer edge. Sol identified this cycle in its bounded read-only review; the
parent has now rechecked the unchanged relevant source index. This is dependency
evidence, not an executed game journey.

Parent static verification parsed all 89 original index cards and checked their
references. Adding the conditional rescue-producer edge yielded exactly
`F01 -> CT04 -> CT02 -> I02 -> F01`. Adding the I02a checkpoint and replacing
only the two named enabling edges removed the cycle; full I02 still depends on
`I01, F01, D02` and remains a direct M1-ACCEPT prerequisite. This is a finite
schedule check, not another required feature or PR count.

The F01 consumer is merged in PR127 at `eee8275`; its synthetic rescue fixture
does not close the producer. An earlier mastery-60 nickname idea remains an
unimplemented content proposal. It is not a prerequisite imposed merely to make
the old schedule acyclic, and this amendment does not approve that nickname rule.

Introduce **I02a, consumer execution readiness**, as an enabling checkpoint:

- Entry: completed H01–H08 and I01, with authentic versioned storage, executor,
  isolation, rollback/retry, privacy, recovery and durable journey evidence.
- Before activating a consumer, identify its exact command/effect requirements
  from the accepted source and actual public owners. The H executor must execute
  each required command completely, including all mandatory residuals, through
  the real transaction. Known unsupported commands remain explicitly rejected.
- Verify the required subset through the actual durable public boundary. Neither
  a switch case, test double, pure PREPARED result nor a future-handler placeholder
  satisfies readiness. Reuse unchanged invariant evidence rather than mirror all
  command payloads in another test catalogue.
- A readiness checkpoint names the consumer and verified subset. It cannot imply
  universal coverage, full F01/D02/I02 or final M1 acceptance.

Replace only the operational I02 entry edge for **W04** and **CT02** with the
corresponding I02a consumer checkpoint. All their other predecessors, source
rules and acceptance remain. H and ID03 are not waived; world/JOIN still require
their real owners, transactions and physical facts. UI may consume only actually
implemented safe capabilities; this amendment authorizes no successful stub.

Keep full **I02** with its original `I01 + F01 + D02` completion requirements
before **M1-ACCEPT**. Complete F01 producer/content/consent/reload/privacy after
its genuine source exists; complete retraining under its accepted finite policy.
No new significance or retraining policy is established here.
