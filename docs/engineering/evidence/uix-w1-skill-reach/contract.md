## Data

Add `skillReach?: readonly { actorId: string; activationId: string; revision: number; skillId: CombatLabSkillId; minimumRange: number; maximumRange: number; cells: readonly CombatLabHex[] }[]` to `CombatLabView`; all row fields required when present.
Core returns one row per learned skill in `getCombatSkills` catalogue order for an active current actor, non-null matching activation and active `sprite-prototype-v3` state only. Unknown/noncurrent/inactive actor, terminal/null activation, M0/v1/v2 or no learned skills → `[]`; server additionally restricts rows to controlled activation. Row revision equals state revision/wire `viewRevision`.
Reuse `COMBAT_SKILLS` metadata, `hexDistance`, `prototypeLineOfSight`, `compareHex` and existing target-admission order. Cells are unique sorted detached copies of finite map hexes excluding blocked cells; include empty and occupied cells without faction/status/incorporeality/morale filtering. Do not derive geometry from target previews or ordinary weapon reach.

| Learned skill    | Spatial geometry                                            | Admission remains separate and unchanged                                                                                                |
| ---------------- | ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `shield-brace`   | Actor cell, 0–0; no LOS filter                              | Self only; sword-shield; repeat brace rejected until next activation.                                                                   |
| `armor-pressure` | Inclusive 1–1; no LOS filter                                | Active enemy, not incorporeal; sword-shield/great-weapon/raider.                                                                        |
| `reach-thrust`   | Inclusive 2–2 with canonical LOS                            | Active enemy, not incorporeal; spear.                                                                                                   |
| `aimed-shot`     | Inclusive 2–4 with canonical LOS (ordinary bow begins at 1) | Active enemy, not incorporeal; bow.                                                                                                     |
| `rally`          | Inclusive 0–2 with canonical LOS, including actor cell      | Active same-side human below maximum morale, including self; excludes beasts/steady creatures/enemies. Existing equipment list applies. |

Learned equipment-incompatible skill or actor with existing threat profile → retain row identity/min/max with `cells: []`. For otherwise capable current actors, low AP/stamina, panic and already-applied brace do not erase passive geometry; existing skill preview/admission still rejects those actions. Rank effects/costs are untouched.
Validator accepts omitted field, `[]` and valid `cells: []`; rejects null/nonarrays/nonrecords/extra row keys, unknown or unlearned skill, duplicate rows/cells, malformed/unsafe coordinates (signed q/r allowed; exact cell keys q/r), foreign/blocked cells, missing/empty identity, negative/unsafe revision or ranges, reversed ranges and mismatched actor/activation/revision. Nonempty rows require active sprite-v3, current controlled active roster actor and supplied `skills` array; compare min/max to supplied skill metadata, never a web rule table. Guard malformed companion collections before traversal, including M0/terminal payloads.
No selection request/storage: emit all learned rows. Downstream selects only `(activation.actorId, activation.id, viewRevision, selectedSkillId)`; pinning another unit cannot change origin. Absent/missing/stale row or explicit empty geometry never falls back to weapon reach while a skill is selected; deselection may restore existing weapon inspection.
`COMBAT_LAB_VERSION` stays 1; old projections may omit the field. Replay “v1–v3” means sprite rulesets, while supported replay schemas are 1 and 2: invent no schema 3. Reprojection may add derived rows without changing saved setup/commands, canonical serialization/state, events, RNG, receipts, rules, admission or costs. All-visible lab only: new rows contain no target IDs, enemy budgets, blocker traces or hidden-state diagnostics; existing public roster pools remain unchanged, with no fog-of-war claim.
