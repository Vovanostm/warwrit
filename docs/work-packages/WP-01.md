# WP-01 — Deterministic Combat Kernel

- Status: Implemented by pull request
- Priority: P0
- Milestone: M0 — Headless Combat Proof
- Requirements: `M0-COMBAT`, `Q-C01` … `Q-C10`
- GitHub issue: `#3`

## Mission

Implement the smallest headless combat system that can prove Warwrit battles terminate, replay exactly, reject invalid actions atomically, and remain independent of UI, network, database, and system time.

## Delivered behavior

- bounded axial hex maps and deterministic shortest paths;
- 4–12 fighters on exactly two M0 sides;
- health, stamina, initiative, accuracy, defense, armor, morale, and bounded wounds;
- individual round initiative with deterministic tie-breaking;
- activation-scoped action points;
- move, attack, defend, wait, and physical retreat commands;
- weapon profiles for sword and shield, spear, great weapon, bow, and simple raider;
- degrading armor, health damage, wounds, death, morale changes, and terminal outcomes;
- explicit seeded RNG state and draw count;
- aggressive and survivor AI doctrines using the same reducer as external commands;
- canonical state serialization and JSON command-stream replay;
- deterministic generated battle fixtures and property-based tests.

## Provisional ruleset

`COMBAT_RULES_V1` is the only numeric source of truth and has ID `m0-prototype-v1` with status `provisional`.

The initial model uses fixed action points, uniform movement cost, recalculated initiative per round, bounded percentage hit chance, one degrading armor layer, threshold wounds, and limited morale/stamina effects. These values support M0 experiments only and require later playtest/balance evidence.

## Non-scope

- React or Babylon battle presentation;
- server endpoints, Colyseus rooms, deadlines, reconnect, or multiplayer ownership;
- PostgreSQL encounter snapshots or receipts;
- campaign/world state, rewards, prisoners, equipment inventory, or progression;
- terrain weights, elevation, cover, line of sight, reactions, or zones of control;
- surrender/captivity and three-side combat;
- final balance claims.

## Acceptance evidence

| Core remains pure                   | architecture checker, zero runtime dependencies, deterministic ESLint policy |

## Review notes

Correctness review must inspect command atomicity, occupancy, resource bounds, terminal immutability, deterministic tie-breaking, replay serialization, and AI fallbacks.

Architecture review must reject transport validation, persistence, UI, ECS, realtime, or campaign behavior inside the kernel and must verify that no numeric rule is duplicated outside the ruleset.

## Exit gate

WP-01 closes only when the exact PR head passes clean checkout, the stress result reports 10,000 resolved battles, migration smoke remains green, the PR diff contains no deferred subsystem, and post-merge `main` CI succeeds.
