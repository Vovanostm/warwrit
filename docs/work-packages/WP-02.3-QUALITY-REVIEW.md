## SSOT / SRP / KISS / YAGNI changes

`economy-coverage.ts` owns interval membership and actual field-worker eligibility;
accrual, financial death and lifecycle interruption share it. It does not merge
new F1 admission and already accepted support into one ability rule.

`economy-payments.ts` owns actual held/unreserved cash settlement; departure code
owns eligibility, due-boundary preparation and the residual physical requirement.
Both default payment and final settlement use one exact oldest-claim ordering.
`claimsForCharacter` makes persistent-person debt scope explicit. `findPoolAccess`
is not a catch-all “ignore access errors” fallback: absent capability means no
optional payment, but an invalid supplied capability fails the entire preparation.

`economy-view.ts` owns the allowlisted observer projection/rejection DTO; the root
preparer still compares that same projection for the sole observed revision.
The move does not change public exports, fields or serialization. No generic
framework, registry, queue, runtime dependency, second wallet or new finance
revision was introduced. Common source identity/normalizer/actor rules and
canonical condition capabilities remain reused, not rewritten.
