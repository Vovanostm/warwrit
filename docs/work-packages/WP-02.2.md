## Executable boundary

`prepareCompanyLifecycle(state, command, trustedContext)` validates admission,
identity, actual graph and command/source authority, then returns either:

- `REJECTED`: identical input state and an internal reason;
- `PREPARED`: unchanged input state, a calculated next lifecycle component and a
  receipt containing events and mandatory cross-component requirements.

**PREPARED is not an aggregate Accepted, commit, publication or queued saga.**
The existing general executor remains unsupported until applicable financial,
item and other effects can commit together. No client `settled=true` bypass exists.
The computed next component is usable by later composition; tests exercising it
are not evidence of completed payroll, item transfers or database transactions.

Implemented branches: CreateCompany, Recruit, JoinFieldParty, SetAssignment,
Arrive, ReturnToService, DesignateHeir, ResolveLeadership, scoped Observe and
RenameCompany. The latter is a small identity-preserving presentation operation.
Other command branches fail closed. This is not implementation of all 43 handlers.

The component tracks command/source identities, rejecting conflicting bodies and
reusing earlier receipts before fresh-revision checks. A retried PREPARED result
must not publish its earlier events again. This is local serializable bookkeeping;
real unique constraints, cross-company races and durable commits belong to 02.7.

## Physical and historical truth

Existing identity/presence/membership primitives are reused. Membership, duty,
location, conditions and encounter binding remain distinct. Family does not imply
service. No social cap of twelve; field parties retain hard maximum six. A lower
Leadership capacity marks overflow without removing people or repeatedly changing
persistent morale. The modifier is derived, not applied to combat in this slice.

Arrival validates the current segment, origin, destination and earliest arrival.
It does not join, feed or pay anyone. Atomic whole-party travel belongs to the
world adapter: a solo Arrive cannot split an existing travelling field party.
ReturnToService can restore actual contact after verified arrival, but cannot
release a captive or resurrect anyone. RECOVERY does not remove the physical slot;
leaving a field duty needs actual verified handover and preserves the position.

Succession consumes an actual crisis and complete trusted graph. A healthy leader
being in an encounter alone is not an incapacity crisis. Missing references reject
rather than proving extinction. Invalid loaded availability, duty and membership intervals also reject, rather than
being interpreted as absence of a successor. Existing remote successors keep their location,
skills, aptitude and perks; no emergency people appear. Minor regency uses an
existing adult company member, with explicit majority restore/confirmation modes.
Loss of an acting regent is a crisis of that actual regent: an existing eligible
replacement can take over while the minor keeps the same identity and nominal role.

HeirBypassed records one crisis. A verified first notification computes one
post-response relation and possible departure intent. Its source-linked contribution
is stored with the event, not copied into base relations. Later social processing
must consume this existing contribution once; no decay engine is implemented here.
An intent never performs physical departure, debt settlement or item seizure.

## Trusted facts and privacy

The context is internal adapter data, not a player-deserialized DTO. Facts are
scoped to company/world, canonical revision and the application tick; atTick is the
verified snapshot/application boundary, not a substitute for historical happenedAt.
Opening facts bind fixed source IDs, seed, culture/location, existing people and
candidate set. Duty handover facts must attest an actual accepted arrangement,
not merely the presence of another person. Graph completeness includes active
service information needed to exclude incompatible service for the loaded people.

State and trusted facts are immutable typed domain inputs. They are not a public
wire state schema. The component never writes to them; new state is a proposed
value. The caller owns snapshot persistence and transaction atomicity.

`COMPANY_OBSERVATION` specifically authorizes lifecycle disclosure for its subject,
including service/family candidacy. It is not any arbitrary witness fact. It stores
a detached snapshot and updates the known candidate list only on that observation.
`projectCompanyLifecycle` reads only these snapshots, never live hidden status.
`projectLifecycleRejection` maps private state-dependent failures to the same public
contact/access error. PREPARED receipts and private states are not network responses.
Full financial noninterference and authenticated HTTP endpoints remain later work.

profiles, three candidate templates, default aptitude and origin contact reactions
in the same catalogue. Existing values are retained. Missing sourced overflow and

repeated in reducers or behavior test expectations.

first concrete component edition (schema 1); no earlier persisted lifecycle state
exists in the repository. This is not a migration of the whole future domain.

catalogue fingerprint is not proof that the original ZIP was obtained.
