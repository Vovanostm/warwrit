# Physical-state implementation checks

This is a review/workflow aid, not a second source of balance or item definitions.
Read the active work-package's canonical Notes and current types first.

## Trace one entity through the whole transition

Item identity, owner, physical container, access authority, equipment placement
and durability are separate. A reference in an offer is not a delivered item;
victory is not permission to seize it. For a split, prove both exact quantities
and predecessor provenance. For a failed transfer, prove unchanged state. A full
receiver during mandatory return needs the existing explicit local-overflow rule,
not deletion, a new copy or continued captivity of the departing member.

For a condition distinguish definition ID from instance ID, causal onset, actual
help, elapsed eligible recovery and persistent scar/history. Resolve capabilities
through one catalogue-backed rule. `basicWork` for foraging and `localDuty` for
service are distinct. An already accepted maintenance cohort is not a new intake.

## Review the compound boundary

Follow resource -> funding -> actual care -> condition change -> capability ->
maintenance -> knowledge. Each arrow must have a source, owner and tick; no
`settled=true`, health default, paid-but-unperformed service, or item+cash double
charge. A stable wound lacks a random death timer; a critical one needs its actual
causal deadline. Full/current pools stay distinct; equipping or increasing a
maximum does not refill the current pool.

A hidden outcome must not reveal new loot, free money, capacity or different
errors before an authorized observation. Run a paired sequence, then reveal it
and reconcile once. Preserve source fan-out for different people/items while
rejecting duplicate delivery of the same effect.

## Representation change

Before turning legacy `conditionIds` into runtime instances, inspect every
`canPerform` caller and both actual/known snapshots. Do not reinterpret IDs in
place or leave two independently writable condition truths. Document an explicit
version/loader route for older nonempty condition lists; missing onset/source
history is not healthy/default history. V1 combat receipts remain unchanged;
V2 conversion and durable SQL composition keep their own work-package scope.
