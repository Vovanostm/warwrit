# Warwrit: текущие профили 2D-графики

Решение владельца от 2026-10-25 записано в
[wiki](../../../docs/wiki/vision.md#основной-стиль-и-профиль-локаций--решение-2026-10-25).

- [graphic-novel.json](graphic-novel.json) — основной «Сдержанный графический роман».
- [fog-wet-stone.json](fog-wet-stone.json) — «Туман и мокрый камень» для явно
  выбранной локации или её окружения. Перечень таких локаций ещё не задан.

`references/graphic-novel/` содержит семь выбранных образцов;
`references/fog-wet-stone/` — шесть пейзажей. Это сохранённые копии выбранных
изображений №2/№5 из сравнения десяти направлений. Старое сравнение и его
промпты не переписаны. Персонаж из варианта №5 не назначен эталоном персонажей:
владелец выбрал этот вариант для некоторых локаций.

## Готовые JSON-запросы для генерации

По уточнению владельца подготовлены отдельные **полностью собранные запросы**,
без профиля, сборщика, метаданных и незаполненных подстановок:

| Стиль                        | Непрозрачная сцена                                            | Прозрачный спрайт                                               |
| ---------------------------- | ------------------------------------------------------------- | --------------------------------------------------------------- |
| Сдержанный графический роман | [graphic-novel-scene.json](requests/graphic-novel-scene.json) | [graphic-novel-sprite.json](requests/graphic-novel-sprite.json) |
| Туман и мокрый камень        | [fog-wet-stone-scene.json](requests/fog-wet-stone-scene.json) | [fog-wet-stone-sprite.json](requests/fog-wet-stone-sprite.json) |

Каждый файл — объект аргументов **встроенного `image_gen`**: строка `prompt`
и флаг `transparent_background`. Это не HTTP-payload OpenAI Image API.
Промпт можно целиком передать в генератор; для другого предмета заменить
секции `SUBJECT` и `COMPOSITION`/`FRAMING`, сохранив выбранный `ART DIRECTION`.
При изменении фактов объекта поправить соответствующие ограничения:
разрушенное состояние относится к старой мельнице, не ко всем зданиям.
Промпты спрайтов используют пример проекции: перед игровым производством
согласовать его с видом-потребителем. Сцена и спрайт — отдельные запросы;
не включать прозрачность в промпт с небом, ландшафтом и атмосферой.

Содержательные секции: назначение, конкретный предмет и его состояние,
кадрирование, техника рисования, иерархия деталей/тона, физически понятный
свет, роль референсов и ограничения. Для туманного спрайта атмосферная
дымка не запекается в альфа-края; влажность задают материалы и палитра.

Веб-источники, прочитанные 2026-10-25:

- [Official OpenAI documentation: Image prompting](https://developers.openai.com/api/docs/guides/image-prompting)
  — явные видимые требования, роли референсов, сохранение инвариантов,
  последовательные адресные изменения; JSON сам по себе не повышает качество.
- [Official OpenAI documentation: Image generation](https://developers.openai.com/api/docs/guides/image-generation)
  — различие генерации/правки и фактическая проверка прозрачности результата.

Рекомендации по структуре применены к выбранным образцам Warwrit; конкретное
художественное содержание принадлежит проекту. Промпты этой версии не
прогонялись: синтаксис и аргументы проверены, качество новых выходов не измерено.

## Как использовать JSON

Это профили задания для генерации, а не готовый формат произвольного API и
не исполняемый генератор. Они не запускают задания или платные сервисы.
Предпочтительный инструмент — встроенный `image_gen`.

1. Выбрать профиль. По умолчанию `graphic-novel`; `fog-wet-stone` — только
   по явному выбору для конкретной локации/ассета, без автоматического правила
   «все болота — туман».
2. Открыть подходящие изображения из `references` и прочитать источник
   предмета/места. Эталон задаёт рисовку; источник места задаёт факты.
3. Выбрать шаблон: `scene`, `portrait`, `character_sprite` или
   `environment_sprite`. Последний подходит зданиям, деревьям, камням
   и реквизиту. У варианта тумана есть только сцена и спрайт окружения.
4. Заполнить все `required_inputs`. В `template.prompt` подставить значения
   вместо `{{имя}}`. Собрать `prompt` из `Use case: stylized-concept.`,
   `style_prompt`, заполненного `template.prompt` и `shared_constraints`.
5. Передать инструменту объект с **двумя полями**: собранным `prompt` и
   `transparent_background` выбранного шаблона. В `example_requests[].arguments`
   уже есть такие объекты. В примерах спрайтов сначала заменить примерные
   проекцию, сторону, освещение, масштаб и опорную точку контрактом нужного вида.

Не отправлять весь профиль как запрос инструмента. Имена файлов внутри текста
не означают, что генератор получил пиксели. Для новой генерации следовать
поддерживаемому режиму инструмента; при правке существующего изображения
сначала просмотреть цель и приложить её предусмотренным инструментом способом.
Не выдавать стилевой образец за цель правки, если нужно нарисовать новый объект:
при сохранении старой сцены генератор может удержать её избыточную фактуру.

## Сцена и спрайт

`scene` — цельная непрозрачная иллюстрация, включая атмосферу и дальние планы.
Остальные шаблоны запрашивают настоящую альфа-прозрачность без нарисованного
фона, шахматки, ореола или встроенной тени на земле. Туман у отдельного спрайта
выражается холодной палитрой и влажным материалом; не запекать серый прямоугольник
или полупрозрачную дымку вокруг объекта. Атмосферу всей локации решать при её
композиции, не размывать лица, входы, пути и предметы взаимодействия.

Камерная проекция иллюстрации не задаёт проекцию игрового спрайта.
Шаблон требует контракт потребляющего вида: оси, сторона, свет, масштаб,
опора ступней/корней/основания/входа. Не сплющивать повторно и не отражать
готовое освещение. Размеры в промптах — запрос, фактический результат проверять.

JSON задаёт новый художественный стандарт для 2D; он не меняет Babylon.js,
камеру или отдельный конвейер 3D-персонажей. Новые примеры спрайтов не
генерировались и не прошли проверку прозрачности/опорных точек в игре.
Перед расширением серии нужен один образец с проверкой рядом с эталоном
и в потребляющей сцене. Точные итоговые промпты и происхождение хранить
с полученными ассетами.
